# k6

Testes de carga da plataforma Adote um Amigo usando k6. Os scripts validam os fluxos principais da API: listagem publica de animais e criacao de solicitacao de adocao.

## Objetivo

- Medir tempo de resposta da API.
- Verificar taxa de falhas durante carga.
- Simular acessos concorrentes.
- Validar se endpoints essenciais continuam respondendo.
- Apoiar a analise das metricas no Prometheus e Grafana.

## Estrutura

```text
load-tests/k6/
|-- animals-list.js      # Carga na listagem publica de animais
|-- adoption-flow.js     # Fluxo de listar animal e criar adocao
`-- k6.md
```

## Pre-requisitos

Suba a stack:

```bash
docker compose up -d --build
```

Opcionalmente, popule animais locais:

```bash
docker compose exec backend npm run seed
```

Verifique se o backend responde:

```bash
curl http://localhost:4000/health
```

## Execucao com Docker Compose

Listagem de animais:

```bash
docker compose --profile load-test run --rm k6 run /scripts/animals-list.js
```

Fluxo de adocao:

```bash
docker compose --profile load-test run --rm k6 run /scripts/adoption-flow.js
```

No container k6, a URL padrao e:

```text
http://backend:4000
```

## Execucao com k6 local

Listagem de animais:

```bash
k6 run -e BASE_URL=http://localhost:4000 load-tests/k6/animals-list.js
```

Fluxo de adocao:

```bash
k6 run -e BASE_URL=http://localhost:4000 load-tests/k6/adoption-flow.js
```

## Variaveis

```text
BASE_URL
```

Define a URL base do backend. Se nao for informada, os scripts usam:

```text
http://backend:4000
```

## Script `animals-list.js`

Endpoint testado:

```text
GET /api/animals?page=1&limit=20&sort=name:asc
```

Cenario:

```text
30s subindo ate 10 usuarios virtuais
1m  subindo ate 25 usuarios virtuais
30s reduzindo para 0 usuarios virtuais
```

Checks:

- Status HTTP `200`.
- Resposta possui `items` em formato de lista.

Thresholds:

```text
http_req_failed: rate<0.05
http_req_duration: p(95)<800
```

Interpretacao:

- Menos de 5% das requisicoes podem falhar.
- 95% das requisicoes devem responder em menos de 800 ms.

## Script `adoption-flow.js`

Fluxo testado:

```text
GET  /api/animals?page=1&limit=1
POST /api/adoptions
```

Cenario:

```text
5 usuarios virtuais durante 1 minuto
```

Checks:

- Listagem retorna status `200`.
- Existe pelo menos um animal.
- Criacao da solicitacao retorna status `201`.

Thresholds:

```text
http_req_failed: rate<0.10
http_req_duration: p(95)<1000
```

Interpretacao:

- Menos de 10% das requisicoes podem falhar.
- 95% das requisicoes devem responder em menos de 1000 ms.

## Payload de adocao

O script cria um payload com dados ficticios:

```json
{
  "applicantName": "Teste k6",
  "applicantEmail": "teste@example.com",
  "applicantPhone": "16999999999",
  "applicantAge": 25,
  "state": "SP",
  "city": "Franca",
  "message": "Tenho interesse em adotar com responsabilidade."
}
```

O `animalId` vem do primeiro animal retornado pela listagem.

## Metricas importantes

```text
http_reqs
http_req_duration
http_req_failed
http_req_waiting
iterations
vus
checks
```

Para apresentacao, destaque:

- total de requisicoes;
- taxa de falhas;
- p95 e p99 de latencia;
- checks aprovados;
- comportamento da API no Grafana durante o teste.

## Relacao com observabilidade

Enquanto o k6 roda, o backend tambem publica metricas em `/metrics`. O Prometheus coleta esses dados e o Grafana exibe:

- requisicoes HTTP por segundo;
- latencia HTTP p95;
- estado da conexao MongoDB.

Isso permite comparar a saida do k6 com o comportamento observado no dashboard.

## Cuidados

- O teste `adoption-flow.js` cria registros reais na colecao `adoptionrequests`.
- Use ambiente local ou de teste.
- Se nao houver animais disponiveis, o fluxo de adocao nao cria solicitacao.
- Aumentar usuarios virtuais pode exigir ajuste em `RATE_LIMIT_MAX`.
